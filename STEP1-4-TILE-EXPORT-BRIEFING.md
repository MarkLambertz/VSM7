# VSM7 App-Wide Export — Concept Briefing

**Status:** UX concept (surface-only), corrected to **app-wide** scope per PO (2026-07-18): export must be **consistent across all Steps I–VII + Implementation**, not a Steps I–IV feature.
**Companion:** [`STEP1-4-EXPORT-CODEX-HANDOFF.md`](STEP1-4-EXPORT-CODEX-HANDOFF.md) (the one shared contract + migration + the consistency fixes Codex must make) · mockup [`design-previews/export-panel.html`](design-previews/export-panel.html).
**Boundary:** Claude owns the export **surface** (one panel, its presets, controls, preview, filename UX, skins, the ⬇ iconography). **Codex owns** canonical extraction, PPT/Word/Excel/PDF generation, download mechanics, tests. The surface never reads canonical data and never makes a file — it *composes one request*.

> This was designed and then **adversarially audited against the live host code** (`exporters.js`, `app.js`, `step1..7.js`, `step6.js`, `focusMode.js`, `step7-ux.html`, `org-chart.html`). The audit found the real inconsistencies that "consistent everywhere" has to fix; they're folded in below and detailed in the handoff.

---

## 1. Vision

> **One** Claude-owned Export panel, opened from **one** ⬇ glyph at **three scopes** (tile · step · app), emitting **one** `export` intent, described by **one** per-tile view-model the host supplies, generated by Codex. So the facilitator sees the *identical* purpose-aware panel on **every** step — tiled or monolithic, Codex-drawn or Claude-embedded, in both skins — with no raw downloads and no completeness percentages.

Purpose-first, because a facilitator thinks in outcomes ("I need a board slide", "the follow-up tracker"), not formats. Choosing a **purpose** collapses a dozen format/scope/include decisions into one, then lets them refine.

---

## 2. The three entry tiers — one glyph, one panel

A single 16px **⬇ "Export…"** icon (never a "Save"/"Download file" verb; a click **never downloads** — it always opens the panel, pre-scoped). Tiers differ only in default scope:

| Tier | Where | Default scope | On which steps |
|---|---|---|---|
| **Tile ⬇** | in the tile action cluster, **immediately left of the ⛶** (so every tile reads `⬇ ⛶`) | `tile` (+ `selection` if the tile has a live selection) | tiled surfaces: I (units, segmentation), III (SCT list), IV (matrix), VI (channel-variety, e2e-routes), VII substeps |
| **Step ⬇** | the per-step header, right-aligned, icon + "Export step" | `step` | **all seven steps + Implementation** — this is what makes monolithic steps (II, V) feel identical to tiled ones |
| **App ⬇** | once in the shell topbar, "Export workshop" | `bundle` (a step/tile checklist) | global; absorbs the current *Report* + *Archive* buttons |

**Iconography law (identical everywhere):** ⬇ tray glyph, `--muted → --blue` on hover; ⬇ sits **left of ⛶** wherever both appear (including the fullscreen tile overlays and Focus Mode, which today omit the cluster — a consistency fix); tile tier icon-only, step/app tiers icon+label; the panel is `position:fixed` so it layers **above** a fullscreened tile.

---

## 3. The one panel — five decisions, in order

A right-docked panel (≈430px), scroll body + pinned footer. It renders **purely from the tile's view-model** — so it *adapts* rather than showing dead controls.

1. **Purpose** — six preset cards; selecting one sets the defaults below (a `customized` badge shows once you override). Each step lands on its **own** sensible default preset (I→exec, II→memo, III→data, IV→data, V→doc, VI→memo, VII→doc, Implementation→appendix).

   Plain outcome names (PO-confirmed 2026-07-18); the **wire id in parentheses is stable** — only the human label changed, so `intent.preset` is unaffected. Each preset's include set is **intersected with the tile's `availableIncludes`** (below), so a preset never turns on data a tile doesn't have.

   | Preset (label) | id | Format | Scope | Default includes |
   |---|---|---|---|---|
   | **Board slide** | `exec` | PowerPoint | tile | scores · gaps |
   | **Workshop record** | `doc` | Word | step | notes · warnings · scores · owners · gaps *(provenance/timestamps off by default — noise in a shared readout; still toggleable)* |
   | **Working spreadsheet** | `data` | Excel | step | scores · owners |
   | **Decision memo** | `memo` | PDF | step | warnings · owners · gaps |
   | **Action tracker** | `follow` | Excel | step | owners · gaps |
   | **Full appendix** | `appendix` | PDF | bundle | everything, dated |

2. **Format** — PowerPoint · Word · Excel · PDF (+ **PNG/SVG only where the view-model allows them**, i.e. the 7.7 org chart — image formats never leak onto text steps). Fitting formats highlight; unusual ones **dim, not block**.

3. **Scope** — tile · selection · step · bundle, with inline counts. A **zero-count** scope renders disabled-with-count; a scope the target genuinely can't have (e.g. `selection` on a monolithic step) is **absent** — the view-model decides which.

4. **Include** — the seven booleans **notes · warnings · scores · owners · provenance · timestamps · unresolved gaps**, but only the ones the target actually has data for (the view-model's `availableIncludes` — the honesty field; a preset's include set is intersected with it, so a preset never promises a section the tile lacks). No completeness %.

5. **Filename** — editable, monospace, defaulted to `VSM7_<project>_<step>-<tile>_<purpose>_<date>.<ext>`; changing format swaps only the extension.

**Preview** — a faithful summary line ("You'll get **PowerPoint** · this tile (22 SCTs) · scores, gaps.") + a schematic thumbnail (slides / page / grid per format). A *promise of shape* rendered from the view-model — not a real render (that's Codex).

**Footer** — Cancel · **⬇ Export ‹Format›** → emits the intent and closes.

## 4. The one intent + one view-model

Emitted from every tier, every step (ids pinned to the host's existing `step1..step7`/`implementation` vocabulary — **not** Roman numerals, which would mis-route on Implementation):

```js
{ evt:'export', api:1, origin:'tile'|'step'|'app',
  stepId:'step1'|…|'step7'|'implementation', tileId:string|null,
  scope:'tile'|'selection'|'step'|'bundle',
  target:{ substeps?:['7.1'…'7.7'], selection?:[{kind,id}], bundle?:[{stepId,tileId,scope}] },
  format:'pptx'|'docx'|'xlsx'|'pdf'|'png'|'svg',
  preset:'exec'|'doc'|'data'|'memo'|'follow'|'appendix'|null,
  options:{notes,warnings,scores,owners,provenance,timestamps,gaps},
  filename, skin, requestId }
```
Host replies `exportReady{requestId,downloadName}` / `exportError{requestId,message}`.

The **view-model** (Codex → surface, per `(stepId,tileId)`; the surface renders from this and nothing else):
```js
{ stepId, tileId, title, kind:'list'|'matrix'|'canvas'|'substeps', count, unitNoun,
  monolithic, defaultPreset, availableFormats:[…], availableScopes:[{kind,label,count}],
  availableIncludes:[subset of the 7], selectable, selection:[{kind,id,label}],
  siblings:[{tileId,title}], project:{name,date}, substeps?:[{id:'7.1',title}] }
```

| **IV** Central/Decentral | contribution matrix | data | xlsx/pptx/pdf | scores·owners·warnings·provenance·timestamps·gaps | Codex / Codex |
| **V** Design Steering *(monolithic)* | steering map | doc | docx/pptx/pdf | notes·warnings·owners·provenance·timestamps·gaps | Codex / Codex |
| **VI** Channels | channel-variety · e2e-routes | memo | **svg/png/pdf/pptx/xlsx** *(keeps today's formats)* | warnings·scores·owners·gaps·provenance·timestamps | Codex / Codex |
| **VII** Representation | 7.6 charter · 7.7 org-chart · all-substep | doc | charter docx/pdf · org-chart **pptx/pdf/svg/png** | owners(RASIC)·gaps·notes·provenance·timestamps·warnings | **Claude** (nested) / Codex |

Step VII's shape is handled by `target.substeps`, **not** new scope words: one substep → `scope:'tile',tileId:'7.4'`; export-all → `scope:'step',target.substeps=[all]`.

## 6. Folding in the existing one-offs (nothing stays a parallel system)

The app already has export — it's just raw and inconsistent. The shared module **re-homes every existing generator behind the one intent**; nothing that downloads today stops working. (Full phased plan in the handoff.)

- **Every step's "Download Outcome"** (raw single-format `.doc`/`.xls` from `exporters.js`) → becomes the **step ⬇** with a default preset that reproduces today's file; other formats/presets are now switchable.
- **Step VI's SVG/PNG/PDF/PPTX menus** (`export-e2e-route`, `export-channel-variety`) → become the two Step VI tiles' formats — **kept, not regressed** to xlsx.
- **Step VII's HTML report** (`exportStep7` Blob) → demoted to an **offline fallback** once Codex's Word/PDF lands; the ⬇ opens the shared panel.
- **7.7 org-chart SVG/PNG** (`buildExportSVG`/`svgToPng`, which bake the honesty watermark/legend) → become the **png/svg formats** available only on that tile; the client renderer is kept as the generator, its bespoke modal retired.
- **Global Report + Archive** buttons → **App ⬇**: Report = `appendix` preset, Archive = an "Advanced → raw project JSON" affordance (round-trip preserved, never a purpose preset).

## 7. Claude vs Codex (one line)

Codex provides stable per-tile/per-step **view-models** → Claude renders the one **surface** → Claude emits **one** `export` intent → Codex **extracts + generates + downloads** and echoes `exportReady`/`exportError`. Claude owns the panel/presets/preview/filename/skin/iconography and mounts it directly only inside Step VII; Codex owns the tile registry, mounting the singleton panel on Steps I–VI + Implementation, the ⬇ trigger placement on host-rendered steps, file generation, tests, cache labels.

---

## 8. The consistency fixes this requires from Codex (the audit's must-fixes)

Because the current export is genuinely inconsistent, "the same everywhere" isn't just a mount — it needs Codex to (detailed in the handoff): **pin one `stepId` vocabulary** (`step1..step7`/`implementation`); make the **step ⬇ a shared header helper** (de-dup step1 & focusMode's duplicates, **add it to step6 and Implementation**, which lack it); add the **tile ⬇ into the fullscreen-tile and Focus-Mode render paths** (they omit the action cluster today); **keep Step VI's four formats**; **reconcile `window.STEP7` (api:2) with the panel bridge (api:1)** and add a nested-panel relay + neutralize the direct `#exportBtn` handler; **absorb both global buttons**; and define the **degraded/vm-absent contract** (what shows before a view-model exists), since `availableIncludes`/`availableFormats` are net-new per-tile host data.
